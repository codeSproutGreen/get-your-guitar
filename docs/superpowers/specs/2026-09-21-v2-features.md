# get-your-guitar v2 기능 정의 (초안)

- 작성일: 2026-09-21 (SDS PC)
- 상태: **초안 — 사용자 확인 대기.** 확정되면 기능별 구현 계획을 `docs/superpowers/plans/`에 쓴다.
- 기준점: v1.0.0 릴리스(태그 `v1.0.0`) = M0 + M1 + 벤딩. v1 설계 스펙은 `2026-09-16-get-your-guitar-v1-design.md`.

v1.0.0은 스펙의 M2(설정)·M3(메트로놈) 없이 나갔다. 그래서 v2는 네 묶음이다: **① 새 요구사항 둘(홀드 서스테인, 음색 개선)**, ② v1에서 넘어온 M2·M3, ③ 원래의 v2 백로그.

## 1. 홀드 서스테인 — 누르고 있는 동안만 소리 (신규 요청, 2026-09-21)

### 요구
음은 손가락으로 누르고 있는 동안만 유지되고, 손을 떼면 멈춘다.

### 지금과 무엇이 다른가
v1은 "탭 = 피킹, 자연 감쇠"였다(v1 스펙 2장, 제스처 표의 "up / cancel: 아무것도 안 함"). 손을 떼도 줄은 계속 울리다 스스로 잦아든다. 이 요구는 그 결정을 뒤집는다. 실제 베이스에 더 가깝다 — 프렛을 짚은 손가락을 떼면 줄이 프렛에서 떨어지며 소리가 죽는다.

| | v1.0.0 | v2 |
|---|---|---|
| 손가락을 떼면 | 아무 일 없음, 자연 감쇠 | 그 손가락이 울린 음이 멈춘다 |
| 짧게 톡 치면 | 길게 울림 | 짧은 스타카토 |
| 길게 누르면 | 차이 없음 | 누른 만큼 울림(자연 감쇠는 그 안에서 계속 진행) |
| 음 길이 조절 | 불가능(다음 피킹까지 울림) | 연주자가 손가락으로 조절 → 쉼표·리듬 표현 가능 |

### 동작 규칙
| 상황 | 동작 |
|---|---|
| 탭하고 누르고 있음 | 울린다. 누르고 있어도 영원히 울리지는 않는다 — 현의 자연 감쇠는 그대로 진행 |
| 손을 뗌 | 그 손가락이 **소유한 줄**의 음을 멈춘다(`NoteOff`) |
| 멈추는 방식 | 뚝 끊지 않는다. 루프 감쇠를 크게 올려 약 30~60 ms에 잦아들게 한다 — 손가락으로 줄을 뮤트하는 소리. 출력 게인만 내리는 페이드보다 자연스럽다 |
| 슬라이드·벤딩 중 | 같은 손가락이 계속 누르고 있으므로 계속 울린다. 떼면 멈춘다. (v1.0.0의 "떼면 벤딩이 원래 음으로 복귀"는 의미가 없어진다 — 어차피 멈추므로) |
| 레이크 | 한 손가락이 훑고 지나간 줄들은 **그 손가락이 화면에 있는 동안 모두 울리고**, 떼면 한꺼번에 멈춘다. 지나간 줄을 바로 멈추면 레이크로 화음을 쌓을 수 없다 |
| 같은 줄에 두 손가락 | 나중에 누른 손가락이 음을 가져간다(v1과 같음). **먼저 누른 손가락을 떼도 멈추지 않는다** — 소유권이 없으므로. 나중 손가락을 떼면: 먼저 누른 손가락이 아직 있으면 그 프렛 음으로 돌아가고(풀오프), 없으면 멈춘다 |
| 개방현 셀 | 다른 셀과 같게 취급(떼면 멈춤). 실제 악기에서는 개방현이 계속 울리지만, "누르는 동안만"이라는 요구를 문자 그대로 따른다. → 열린 결정 1 |
| 띠 스크롤 | 영향 없음 |
| 앱이 백그라운드로 | v1과 같음(`AllNotesOff`) |

**해머온·풀오프가 덤으로 생긴다.** "같은 줄에 두 손가락" 규칙은 홀드 의미론에서 자연스럽게 나온다: 한 손가락으로 5프렛을 누른 채 다른 손가락으로 7프렛을 치면 7프렛 음(해머온), 그 손가락을 떼면 5프렛 음으로 복귀(풀오프). 다시 튕기지 않고 음높이만 옮기는 경로(`Slide`)가 이미 있어 추가 합성 작업이 없다.

### 설계 변경
- **`:core` 커맨드**: `NoteOff(string)` 추가(타입 번호는 새로 할당, 기존 번호 불변).
- **`Voice`**: `noteOff()` 추가. `silence()`(2 ms 페이드, `AllNotesOff`용)와 구분한다. 구현은 루프 피드백 `g`를 릴리스 값(예: 0.90)으로 바꾸고, 다음 `noteOn`에서 원래 값으로 복구. 테스트: `noteOff` 후 60 ms 안에 −40 dB, 클릭 없음, 직후 `noteOn`이 정상 음량.
- **`FretboardTouchTracker`**: 줄별 "누르고 있는 포인터 스택"을 들고 소유권을 관리한다. up 시 소유자면 `NoteOff` 또는 풀오프(`Slide`로 이전 프렛 복귀). 레이크로 얻은 줄들도 그 포인터의 소유 목록에 넣는다. 순수 Kotlin이라 전부 JVM 단위 테스트로 고정한다.
- **하이라이트**: 1.5 s 페이드 대신 **누르고 있는 동안 켜져 있고 떼면 짧게 사라짐**. 소리와 표시가 일치해야 한다.
- **감쇠 슬라이더(M2)의 의미**: "음이 얼마나 오래 울리나"에서 "누르고 있을 때 얼마나 오래 버티나"로 바뀐다. 기본값을 길게(0.85 안팎) 잡는 편이 맞다 — 길이는 이제 손가락이 정한다.
- **모드 설정**: `sustainMode = HOLD | RING`. 기본 `HOLD`. `RING`은 v1.0.0 동작(떼도 울림)으로, 하프처럼 울리게 두고 싶을 때를 위해 남긴다. 구현 비용이 거의 없다(추적기가 `NoteOff`를 안 보내면 됨).

### 위험
- **멀티터치 up 이벤트 누락**: 어떤 이유로든 up을 못 받으면 음이 영원히 남는다(자연 감쇠가 있어 무한은 아니지만 길다). `cancelAll`과 제스처 코루틴 취소 시 소유한 줄 전부에 `NoteOff`를 보내야 한다. 테스트로 고정.
- **체감 지연**: 떼는 순간의 반응도 지연 대상이 된다. 같은 커맨드 큐를 타므로 v1에서 측정한 경로(버퍼 8 ms) 그대로다.

## 1-2. 음색 개선 (피드백, 2026-09-21: "소리가 구리다")

### 지금 소리는 어디서 나오나
녹음된 소리가 아니다. 외부 라이브러리도 샘플 파일도 없다(앱 1.4 MB 전부가 코드). `:core`의 `KarplusStrongVoice`가 **실시간으로 계산해 만든다**: 짧은 백색 노이즈를 한 주기 길이의 딜레이 라인에 넣고, 1극 로우패스와 감쇠를 거치며 되돌려 넣는 1983년의 Karplus-Strong 알고리즘. 계산이 싸고 음높이를 연속으로 바꿀 수 있어(슬라이드·벤딩) v1 스펙이 "합성으로 시작, 샘플로 교체 가능"으로 정했다.

### 왜 구리게 들리나 (추정 원인, 큰 것부터)
1. **폰 스피커가 베이스 음역을 못 낸다.** 개방현 기음이 41~98 Hz, G줄 12프렛도 196 Hz인데 폰 스피커는 대략 250 Hz 아래를 거의 재생하지 못한다. 기음은 사라지고 배음만 들려 얇고 앵앵거린다. **실제 베이스를 녹음한 샘플을 써도 폰 스피커에서는 같은 문제가 남는다.** 이어폰·스피커로 들었는지 확인이 먼저다.
2. **여기(피킹) 신호가 백색 노이즈다.** 실제 현은 손가락이 당겼다 놓는 삼각형 변위로 시작한다. 노이즈는 어택이 "칙" 하고, 칠 때마다 음색이 조금씩 다르다. 기본 Karplus-Strong이 하프시코드·장난감 기타처럼 들리는 주된 이유.
3. **악기의 몸이 없다.** 픽업 위치(특정 배음이 빠지는 빗살 필터), 픽업·앰프의 고역 롤오프, 저역의 두께가 전혀 모델링돼 있지 않다. 현 하나만 허공에서 울리는 소리다.
4. **소프트 클립이 항상 왜곡한다.** `x / (1 + |x|)`는 선형 구간이 없다. 입력 0.1에서 이미 9%, 0.3에서 23% 눌린다 → 보통 음량에서도 배음 왜곡과 혼변조(화음이 탁해짐)가 생긴다.
5. 터치 세기가 없어 모든 음이 같은 세기·같은 밝기다(v1 결정). 연주가 기계적으로 들린다.

### 개선안
| 안 | 내용 | 장단점 |
|---|---|---|
| **A. 합성 개선** | 여기 신호를 삼각 변위 + 소량의 노이즈로, 픽 위치 빗살 필터, 출력단 "픽업+앰프" EQ(저역 셸프 부스트, 3~4 kHz 롤오프), 선형 구간이 있는 리미터로 교체, (선택) 터치 면적/압력 → 세기 | 에셋 0, 앱 크기 그대로, 슬라이드·벤딩·홀드 서스테인과 그대로 호환. `:core`만 고치므로 전부 단위 테스트 가능. **폰 없이 PC에서 WAV로 렌더해 전/후를 들어 비교할 수 있다.** 한계: 진짜 악기 소리는 아니다 |
| **B. 샘플 음원** | 실제 베이스를 줄마다 몇 프렛 간격으로 녹음한 샘플을 가변 속도로 재생 | 가장 진짜 같다. 가변 속도 재생이라 벤딩·슬라이드도 되고(±3반음 넘으면 음색이 변질), `noteOff`는 릴리스 포락선이면 된다. 비용: **쓸 수 있는 라이선스의 샘플 확보**(CC0 등), 앱 크기(수~수십 MB), 로딩·메모리, 재피킹 전환 처리. `Voice` 인터페이스 뒤라 구조 변경은 없다 |
| **C. A 먼저, 부족하면 B** | A를 하고 WAV·실기기로 들어 본 뒤 결정 | 권장. A는 작고 빠르며, B로 가더라도 출력단 EQ·리미터·세기는 그대로 쓰인다 |

### 검증 방법
`:core`에 테스트 전용 WAV 렌더러를 둔다(짧은 프레이즈: 개방현 4개, 12프렛 위 음, 슬라이드, 벤딩, 화음). 변경 전/후 파일을 `build/` 아래에 써서 PC 스피커·이어폰으로 비교한다. 폰 스피커 문제와 합성 문제를 분리해서 판단할 수 있다.

## 4. 제안 순서

1. **음색 개선 A안 + WAV 비교** — "소리가 구리다"는 앱의 첫인상을 좌우한다. 작고, 다른 기능과 독립적이다.
2. **홀드 서스테인** — 연주감의 근본을 바꾼다. 이후 기능(설정의 감쇠 기본값, 녹음 포맷)이 이 결정에 의존한다.
3. **설정 화면** — `sustainMode`·벤딩 폭·감쇠를 손으로 맞춰 볼 수 있어야 1번의 기본값을 정할 수 있다.
4. **메트로놈** — 연습 도구로서의 완성.
5. **실제 프렛 간격** — 훅이 있어 작다.
6. **5현/튜닝** → **녹음/재생**. **샘플 음원(B안)**은 1번 결과에 따라 앞당기거나 뺀다.

## 5. 열린 결정 (사용자 확인 필요)

0. **어떻게 들었나**: 폰 스피커인가 이어폰인가. 폰 스피커라면 저음이 안 나는 건 음원을 바꿔도 해결되지 않는다. 그리고 음색은 A안(합성 개선) 먼저로 갈지, 바로 B안(샘플)으로 갈지.

1. **개방현**: 떼면 멈춤(요구를 문자 그대로) vs 개방현만 계속 울림(실제 악기). 초안은 "멈춤".
2. **`RING` 모드를 남길지**: 초안은 설정으로 남김(기본은 `HOLD`).
3. **v2의 범위와 순서**: 위 4장대로 갈지. 특히 설정·메트로놈을 v2로 부를지, v1.1·v1.2로 나눠 먼저 낼지.
